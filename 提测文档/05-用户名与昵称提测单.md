# BugNest 提测单

## 1. 本次开发内容

- 本次提测范围：用户名生成、用户名预览、用户名唯一性校验和昵称修改。
- `nickname` 保存原始 Unicode 文本；`user_name` 为创建后不可修改的唯一用户名。
- 默认用户名通过 ICU4J `Any-Latin; Latin-ASCII` 生成。
- 用户名预览为无状态检查，不预留用户名。

## 2. 需求 / Issue

- 需求：支持多语言昵称生成可用的 ASCII 用户名，并允许修改昵称。
- Issue 编号：未提供，待补充。

## 3. 改动范围

- 新增 `UsernameGenerator`，处理 NFKC、ICU 转写、小写化、符号清洗、长度限制和空结果回退。
- 新增用户名预览接口。
- 新增独立昵称修改接口。
- `user_name` 创建后无普通更新路径，`nickname` 可独立修改。

## 4. 接口变化

| 方法 | 路径 | 请求 | 成功响应 | 失败响应 |
|---|---|---|---|---|
| POST | `/auth/sign-up/username-preview` | `nickname` 必填；`userName` 可选 | `200 OK`：`{"userName":"zhang_san","available":true}` | `400 Bad Request`：昵称或手动用户名格式错误；`409 Conflict`：无法生成可用用户名；数据库基础设施异常未统一定义 |
| PATCH | `/accounts/{id}/nickname` | `{"nickname":"新昵称"}` | `204 No Content` | `400 Bad Request`：昵称为空或超过 50 个字符；`404 Not Found`：账户不存在；数据库基础设施异常未统一定义 |
| POST | `/auth/sign-up` | 可选提交 `userName`；手动值仅允许 `^[a-z0-9_]+$` | `201 Created`：`{"userId":123}` | `400 Bad Request`：用户名格式错误；`409 Conflict`：手动用户名冲突 |

## 5. 数据库变化

- 数据库：PostgreSQL。
- Migration：V2 将原 `username` 列改为 `nickname`，并将空值回填为 `user_name`。
- 表/字段：`user_name VARCHAR(30)`、`nickname VARCHAR(50)`。
- 约束/索引：`user_name` 非空、唯一且符合小写字母/数字/下划线格式；`nickname` 非空。
- 运行时使用情况：预览接口查询 `user_name` 可用性；昵称修改只更新 `nickname`，不更新 `user_name`。

## 6. 正常流程

- [ ] 输入 `张三`，预览得到 `zhang_san` 或带数字后缀的可用候选值。
- [ ] 输入 `Иван`，预览得到 ASCII 用户名候选值 `ivan`。
- [ ] 输入 `Müller`，预览得到 `muller`。
- [ ] 输入合法手动用户名 `custom_user`，返回其可用状态。
- [ ] 修改已存在账户昵称后返回 `204`，再次查询账户时 `user_name` 保持不变。

## 7. 异常流程

- [ ] 手动用户名包含大写字母、空格、连字符或其他符号时返回 `400`。
- [ ] 手动用户名已存在时，预览返回 `available:false`，最终注册返回 `409`。
- [ ] 昵称为空或超过 50 个 Unicode code point 时返回 `400`。
- [ ] 只有符号或表情的昵称预览回退到 `user` 基础值并检查唯一性。
- [ ] 预览成功后并发创建同名用户名，最终注册仍以数据库唯一约束为准。
- [ ] 修改不存在账户的昵称时返回 `404`。

## 10. 风险点

- 预览接口不预留用户名，预览结果可能在最终注册前被其他请求占用。
- ICU4J 或转写规则未来升级不会重新生成已经创建的 `user_name`，但新用户结果可能变化。
- 手动用户名不自动改写，格式错误和冲突需要用户重新输入。
- 当前没有普通用户修改 `user_name` 的接口。

## 11. 已知问题

- 当前全量测试中，用户名单元测试通过；依赖 Docker 的数据库集成测试未能执行。
- 用户名预览和最终注册的错误响应尚未统一为结构化错误 JSON。
- 用户名回退和随机后缀只在有限重试次数内执行，超过次数返回冲突错误。

## 12. 验收标准

1. [ ] 中文、俄文和带重音拉丁文字能够生成稳定的 ASCII 用户名基础值。
2. [ ] 生成结果只包含小写 `a-z`、数字和下划线，且不超过 30 个字符。
3. [ ] 昵称原文保存在 `nickname`，不得被拉丁化结果覆盖。
4. [ ] 用户名冲突时预览准确返回不可用，最终注册返回 `409`。
5. [ ] 修改昵称成功后，`user_name` 不发生变化。
6. [ ] 用户名生成、预览和昵称修改相关测试通过。
