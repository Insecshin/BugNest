# BugNest 用户管理提测单

## 1. 本次开发内容

- 提供用户创建、列表查询、详情查询、名称更新和删除能力。
- 增加用户名非空校验和用户不存在异常处理。
- 当前使用内存仓储保存用户数据。

## 2. 需求 / Issue

- 提供缺陷管理平台的基础用户管理 REST API。
- 为后续接入持久化数据库提供分层结构：Controller → Service → Repository。
- Issue 编号：未提供，待补充。

## 3. 改动范围

- 本次提测范围：用户管理模块，包括用户 Controller、Service、Model、DTO、内存 Repository 和全局异常处理。
- 涉及接口：`/users`、`/users/{id}`。
- 不包含 PostgreSQL 用户表的实际读写验收，数据库迁移另见数据库迁移提测单。

## 4. 接口变化

| 方法 | 路径 | 请求 | 成功响应 | 失败响应 |
|---|---|---|---|---|
| POST | `/users` | `{"username":"Noah"}` | `201`，返回 `{"id":1,"username":"Noah"}` | 用户名为空时 `400`，文本 `Username must not be blank` |
| GET | `/users` | 无 | `200`，返回用户数组 | 无 |
| GET | `/users/{id}` | 路径参数 `id` | `200`，返回用户对象 | 用户不存在时 `404`，文本 `User not found` |
| PUT | `/users/{id}` | `{"username":"Alice"}` | `200`，返回更新后的用户对象 | 用户名为空时 `400`；用户不存在时 `404` |
| DELETE | `/users/{id}` | 路径参数 `id` | `204`，无响应体 | 用户不存在时 `404`，文本 `User not found` |

## 5. 数据库变化

- 数据库：本模块接口运行时不连接数据库。
- Migration：不执行用户表 Migration；数据库结构由独立数据库迁移模块负责。
- 表/字段：接口不读写 `app_users`。
- 约束/索引：不适用。
- 运行时使用情况：使用 `MemoryUserRepository` 的 `HashMap`，应用重启后数据清空。

## 6. 正常流程

1. 调用 `POST /users` 创建 `Noah`，确认返回 `201` 和用户 ID。
2. 调用 `GET /users`，确认列表包含 `Noah`。
3. 调用 `GET /users/1`，确认返回用户详情。
4. 调用 `PUT /users/1` 将名称改为 `Alice`，确认返回 `200` 且 ID 不变。
5. 调用 `DELETE /users/1`，确认返回 `204`。
6. 再次调用 `GET /users/1`，确认用户已不存在。

## 7. 异常流程

- 创建用户时 `username` 为 `null`、空串或全空白，返回 `400`。
- 更新用户时 `username` 为 `null`、空串或全空白，返回 `400`。
- 查询、更新或删除不存在的 ID，返回 `404`。
- 请求体缺失、JSON 格式错误或缺少 `username` 时，应返回请求错误；具体格式由 Spring 默认处理，需记录实际结果。
- 传入无法转换为 Long 的路径 ID 时，应返回参数绑定错误。

## 9. 测试数据

- 创建数据：`{"username":"Noah"}`、`{"username":"Alice"}`。
- 更新数据：将 `Noah` 更新为 `Alice`。
- 异常数据：`{"username":""}`、`{"username":"   "}`、`{"username":null}`。
- 不存在 ID：`999`。
- 无预置账号，无登录和鉴权流程。

## 10. 风险点

- 用户数据仅保存在内存中，重启后丢失。
- `HashMap` 内存仓储不适合多实例和并发生产场景。
- 当前无 Bean Validation，请求体错误主要依赖业务判断或 Spring 默认处理。
- 用户接口模型只有 `id` 和 `username`，与数据库迁移中的用户表字段不一致。

## 11. 已知问题

- 用户 CRUD 尚未接入 PostgreSQL。
- 尚未提供完整的 HTTP 层用户接口自动化测试，现有测试以 Service/Repository 单元测试为主。
- 无鉴权、权限控制、分页和持久化能力。
- Issue 编号和正式测试环境地址未提供。

## 12. 验收标准

- [ ] 能成功创建用户并返回 HTTP 201、正数 ID 和用户名。
- [ ] 用户列表和详情查询结果正确。
- [ ] 能更新用户名称且 ID 保持不变。
- [ ] 能删除用户并返回 HTTP 204，删除后查询返回 HTTP 404。
- [ ] 空、空串、全空白用户名创建/更新均返回 HTTP 400。
- [ ] 不存在用户 ID 的查询、更新、删除均返回 HTTP 404。
- [ ] 验收记录明确：当前数据为内存数据，应用重启后清空属于已知行为。
