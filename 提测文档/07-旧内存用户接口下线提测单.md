# BugNest 提测单

## 1. 本次开发内容

- 本次提测范围：旧 `/users` 内存用户接口下线和兼容代码隔离。
- 旧 `User`、`UserService`、`UserRepository`、`MemoryUserRepository` 继续保留给测试或兼容代码。
- 旧 Controller、Service 和 Memory Repository 不再注册为生产 Spring Bean。
- 正式用户链路统一使用 `/auth/sign-up` 和 `Account`。

## 2. 需求 / Issue

- 需求：停止旧内存用户接口作为生产账户入口，避免与 PostgreSQL Account 链路并存。
- Issue 编号：未提供，待补充。

## 3. 改动范围

- 移除旧 `UserController` 的生产 Controller 注册。
- 移除 `MemoryUserRepository` 的生产 Repository 注册。
- 移除 `UserService` 的生产 Service 注册。
- 删除依赖无数据库上下文的旧应用测试，保留旧内存单元测试。

## 4. 接口变化

| 方法 | 路径 | 请求 | 成功响应 | 失败响应 |
|---|---|---|---|---|
| POST | `/users` | 旧用户创建请求 | 无；接口不再注册 | `404 Not Found` |
| GET | `/users` | 无 | 无；接口不再注册 | `404 Not Found` |
| GET | `/users/{id}` | 路径参数 `id` | 无；接口不再注册 | `404 Not Found` |
| PUT | `/users/{id}` | 旧用户更新请求 | 无；接口不再注册 | `404 Not Found` |
| DELETE | `/users/{id}` | 路径参数 `id` | 无；接口不再注册 | `404 Not Found` |
| POST | `/auth/sign-up` | Account 注册请求 | `201 Created`：返回 `userId` | 按新注册链路返回 `400` 或 `409` |

## 5. 数据库变化

- 数据库：本模块无新增数据库结构；正式账户使用 PostgreSQL `app_users`。
- Migration：本模块不新增 Migration；共用 V1+V2 最终结构。
- 表/字段：旧内存接口不读写数据库；新账户链路使用 `app_users`。
- 约束/索引：旧内存接口不适用；新账户链路遵循用户名、邮箱和昵称约束。
- 运行时使用情况：Spring 应用上下文不创建旧内存组件，生产账户只使用 `JdbcAccountRepository`。

## 6. 正常流程

- [ ] 启动应用后，调用 `POST /auth/sign-up` 能进入 Account 注册链路。
- [ ] 注册成功后账户数据出现在 PostgreSQL `app_users`。
- [ ] 旧 `User` 和 `MemoryUserRepository` 单元测试仍可独立运行。
- [ ] 应用上下文中不存在 `UserController`、`UserService` 和 `MemoryUserRepository` 生产 Bean。

## 7. 异常流程

- [ ] 调用任意旧 `/users` 接口均返回 `404`，不得创建或修改内存用户。
- [ ] 应用启动时不得因旧 User 组件缺少 Bean 而失败。
- [ ] 新注册接口不得回退到 `MemoryUserRepository`。
- [ ] 旧接口请求不得修改 PostgreSQL `app_users`。

## 10. 风险点

- 依赖旧 `/users` 接口的客户端会收到 `404`，需要迁移到 Account 接口。
- 旧内存类仍存在于源码中，误将其重新加上 Spring 注解可能导致双实现并存。
- 旧内存数据不会迁移到 PostgreSQL。
- 本模块不提供旧接口数据兼容或自动迁移。

## 11. 已知问题
