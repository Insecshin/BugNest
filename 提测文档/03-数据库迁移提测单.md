## 5. 数据库变化

- 数据库：PostgreSQL 18.6；Local 默认连接 `jdbc:postgresql://localhost:5432/bugnest`。
- Migration：新增 `V1__create_app_users.sql`，Flyway 位置为 `classpath:db/migration`，默认 schema 为 `public`。
- 表/字段：创建 `public.app_users`；字段为 `user_id BIGINT`、`user_name VARCHAR(30)`、`username VARCHAR(50)`、`email VARCHAR(254)`、`password_hash TEXT`、`created_at TIMESTAMPTZ`。
- 约束/索引：`user_id` 主键和身份生成；`user_name` 唯一且限制为小写字母/数字/下划线；`email`、`username` 非空白检查；创建 `uq_app_users_email_ci` 唯一索引。
- 运行时使用情况：Flyway 负责执行结构迁移；当前用户 CRUD 仍使用 `MemoryUserRepository`，不读写 `app_users`。

## 6. 正常流程

1. 准备 PostgreSQL 18.6 和 `BUGNEST_DB_USER`、`BUGNEST_DB_PASSWORD` 环境变量。
2. 使用 Local 配置启动应用，连接默认或指定的 `BUGNEST_DB_URL`。
3. Flyway 执行 V1 Migration。
4. 检查 `public.app_users`、6 个字段、约束、索引和 `flyway_schema_history` 中 version `1` 的成功记录。
5. 运行 Testcontainers 集成测试，确认迁移结构断言全部通过。

## 7. 异常流程

- 数据库地址不可用时，应用连接或 Flyway 启动失败。
- `BUGNEST_DB_USER` 或 `BUGNEST_DB_PASSWORD` 缺失时，Local 数据源无法正常连接。
- 已执行 Migration 被修改或校验不一致时，Flyway 应阻止迁移并报告校验错误。
- 已存在不兼容的 `app_users` 结构时，V1 执行可能失败；首次接入既有手工数据库前需单独 baseline。
- 数据库版本或权限不满足要求时，建表、建约束或建索引可能失败。

## 10. 风险点

- Migration 执行失败会阻止应用启动或数据库结构初始化。
- 用户表字段设计与当前 Java `User` 模型不一致，后续持久化接入需要重新确认映射。
- 邮箱唯一索引使用 `lower(btrim(email))`，但当前没有用户接口写入该表，无法通过 CRUD 验证完整业务约束。
- Local 配置依赖真实 PostgreSQL 和环境变量，环境差异可能导致测试结果不同。
