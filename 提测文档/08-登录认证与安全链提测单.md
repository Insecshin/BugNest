# BugNest 提测单

## 1. 本次开发内容

- 本次提测范围：`POST /auth/login` 登录认证、Spring Security 会话与 CSRF、账户昵称访问控制、Redis 登录限流。
- 支持使用邮箱或用户名登录；密码继续采用注册链相同的 NFC 规范化和 Argon2id 校验。
- 登录成功后轮换 Session ID，将认证上下文保存到 Redis Session，并只返回账户公开字段。
- 未知账户执行 dummy Argon2id 校验；未知账户与密码错误返回相同的 `401` 响应。
- 新增 IP 令牌桶和账户连续失败渐进冷却；Redis 不可用时登录失败关闭并返回 `503`。
- 登录、注册、用户名预览和昵称修改统一纳入 CSRF 防护；昵称修改仅允许当前登录账户操作本人数据。

## 2. 需求 / Issue

- 需求：落地企业级 `POST /auth/login` 业务链，并由 Spring Security 管理认证、Session、CSRF 和授权流程。
- 需求：通过 Redis 限制 IP 请求频率和账户连续认证失败，避免暴力破解，同时不永久锁定账户。
- Issue 编号：未提供，待补充。

## 3. 改动范围

- 本次提测范围：登录过滤器、认证 Provider、登录成功/失败处理器、安全配置、CSRF 获取接口、Redis 限流、客户端 IP 解析、昵称更新授权及相关自动化测试。
- 新增 Spring Security、Spring Session Data Redis 和 Jackson Starter 依赖。
- `AccountRepository` / `JdbcAccountRepository` 新增按 `user_name` 查询账户，用于用户名登录。
- `PasswordPolicy` 提供登录密码 NFC 规范化能力，与注册链保持一致。
- Session 空闲超时配置为 30 分钟，Redis namespace 为 `bugnest:sessions`。
- 新增 `BUGNEST_RATE_LIMIT_HMAC_KEY` 和 `BUGNEST_TRUSTED_PROXIES` 环境配置。
- 本次未新增或修改 Flyway Migration，未改变 `app_users` 表结构。

## 4. 接口变化

| 方法 | 路径 | 请求 | 成功响应 | 失败响应 |
|---|---|---|---|---|
| GET | `/auth/csrf` | 无；可匿名访问 | `200 OK`：`{"headerName":"X-CSRF-TOKEN","token":"..."}`，同时建立或沿用 Session Cookie | 基础设施异常未统一定义 |
| POST | `/auth/login` | `Content-Type: application/json`；携带 Session Cookie 和 CSRF 请求头；请求体 `{"identifier":"邮箱或用户名","password":"密码"}` | `200 OK`：`{"userId":123,"userName":"zhang_san","nickname":"张三"}`；轮换 Session ID | `400 INVALID_REQUEST`；`401 AUTHENTICATION_FAILED`；缺少/错误 CSRF 时 `403 FORBIDDEN`；限流时 `429 RATE_LIMITED` 并带 `Retry-After`；Redis 不可用时 `503 AUTHENTICATION_UNAVAILABLE` |
| POST | `/auth/sign-up` | 原注册请求不变；现在必须携带 Session Cookie 和 CSRF 请求头 | `201 Created`：`{"userId":123}` | 缺少/错误 CSRF 时 `403 FORBIDDEN`；原有参数错误 `400`、账户冲突 `409` |
| POST | `/auth/sign-up/username-preview` | 原预览请求不变；现在必须携带 Session Cookie 和 CSRF 请求头 | `200 OK`：返回 `userName`、`available` | 缺少/错误 CSRF 时 `403 FORBIDDEN`；原有参数错误 `400` |
| PATCH | `/accounts/{id}/nickname` | 必须登录；携带认证 Session Cookie、最新 CSRF 请求头；请求体 `{"nickname":"新昵称"}` | `204 No Content` | 未登录 `401 UNAUTHENTICATED`；缺少/错误 CSRF 或修改他人账户时 `403 FORBIDDEN`；昵称无效 `400`；账户不存在 `404` |

## 5. 数据库变化

- 数据库：账户继续使用 PostgreSQL；Session 和登录限流状态使用 Redis。
- Migration：无新增或修改；继续使用现有 Flyway V1、V2。
- 表/字段：`app_users` 表结构不变；登录新增读取 `user_id`、`user_name`、`email`、`password_hash`、`nickname`、`created_at`，不写入登录状态字段。
- 约束/索引：沿用 `user_name` 唯一约束和邮箱大小写不敏感唯一索引；本次无新增约束或索引。
- 运行时使用情况：邮箱登录调用 `findByEmail`，用户名登录调用 `findByUserName`；Redis 保存 `bugnest:sessions` 会话、IP 令牌桶和账户失败/冷却状态。未知标识和 IP 使用 HMAC-SHA256 后写入 Redis 键，不保存原始值。

## 6. 正常流程

1. [ ] 调用 `GET /auth/csrf`，保存响应 Cookie，并读取响应中的 `headerName` 和 `token`。
2. [ ] 使用 Cookie、CSRF 请求头和正确邮箱/密码调用 `POST /auth/login`，验证返回 `200` 及 `userId`、`userName`、`nickname`。
3. [ ] 验证登录响应不包含邮箱、明文密码或密码哈希。
4. [ ] 验证登录成功后的 `__Host-bugnest_session` 与登录前 Session ID 不同，且包含 `Path=/`、`HttpOnly`、`Secure`、`SameSite=Lax`，不包含 `Domain`。
5. [ ] 使用登录后的 Cookie 再次调用 `GET /auth/csrf`，验证 token 已刷新。
6. [ ] 携带认证 Cookie 和新 CSRF token 修改本人昵称，验证返回 `204`，数据库昵称更新成功。
7. [ ] 使用用户名和相同密码重新登录，验证同样返回 `200`。
8. [ ] 使用 NFD 形式输入已按 NFC 注册的 Unicode 密码，验证能够正常登录。
9. [ ] 制造若干失败后使用正确密码登录，验证成功后对应账户失败状态从 Redis 清除。

## 7. 异常流程

1. [ ] 不携带 CSRF token 调用登录、注册或用户名预览，验证返回 `403 FORBIDDEN`。
2. [ ] 使用错误密码和不存在账户分别登录，验证均返回完全相同的 `401`：`{"code":"AUTHENTICATION_FAILED","message":"用户名或密码错误"}`。
3. [ ] 使用非 JSON Content-Type、非法 JSON、`null` 请求体、空标识、超长标识、超长密码或超过 8192 字节请求体，验证返回 `400 INVALID_REQUEST`。
4. [ ] 连续制造 5 次账户认证失败，再通过该账户的邮箱或用户名登录，验证共享同一冷却状态并返回 `429 RATE_LIMITED`。
5. [ ] 验证第 5 次失败后冷却约 30 秒，后续失败按 60、120 秒递增，最大 900 秒；冷却期内请求不延长等待时间。
6. [ ] 同一 IP 连续消耗 30 个令牌后继续登录，验证返回 `429` 并带有效 `Retry-After`。
7. [ ] 停止 Redis 后发起登录，验证返回 `503 AUTHENTICATION_UNAVAILABLE`，响应不得暴露 Redis 内部异常。
8. [ ] 使用已登录账户修改其他账户昵称，验证返回 `403 FORBIDDEN`，目标数据不变。
9. [ ] 未登录访问昵称修改接口或其他受保护接口，验证返回 `401 UNAUTHENTICATED`。
10. [ ] 从未配置为可信代理的来源伪造 `X-Forwarded-For`，验证限流仍使用连接对端 IP。

## 10. 风险点

- Session Cookie 强制 `Secure`；直接使用 HTTP 的浏览器不会回传该 Cookie，测试和部署入口必须提供 HTTPS。
- Redis 是登录和 Session 的关键依赖；Redis 故障时系统按失败关闭策略拒绝登录，已登录会话也可能无法恢复。
- `BUGNEST_RATE_LIMIT_HMAC_KEY` 少于 32 字节会导致应用启动失败；不同实例必须使用相同且稳定的密钥。
- `BUGNEST_TRUSTED_PROXIES` 配置错误可能导致所有用户共享代理 IP 限流，或错误信任伪造的转发地址。
- 邮箱和用户名共享账户失败次数，能阻止别名绕过，但攻击者也可能触发最长 15 分钟的临时账户冷却。
- 登录成功会使旧 CSRF token 失效；客户端必须在登录后重新调用 `/auth/csrf`。
- IP 与账户限流状态有过期时间，测试用例需隔离 Redis 键或在用例结束后清理，避免相互影响。
