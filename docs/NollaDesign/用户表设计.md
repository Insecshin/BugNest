# 用户表设计

## 设计结论

用户表命名为 `app_users`。`user_id` 是数据库生成的内部主键；`user_name` 是创建后不可修改的唯一登录用户名；`nickname` 是可修改的用户昵称；`email` 是唯一登录邮箱。

当前 `V1__create_app_users.sql` 仍使用 `username` 字段表示昵称。已执行迁移不得修改，后续通过新的 Flyway 迁移将 `username` 重命名为 `nickname`。

## 字段

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `user_id` | `BIGINT` | 主键、数据库自动生成 | 业务表外键；注册响应返回 `userId` |
| `user_name` | `VARCHAR(30)` | 非空、唯一、仅小写字母/数字/下划线 | 创建后不可修改的登录用户名 |
| `nickname` | `VARCHAR(50)` | 非空 | 用户原始昵称，可修改 |
| `email` | `VARCHAR(254)` | 非空、大小写不敏感、唯一 | 登录邮箱 |
| `password_hash` | `TEXT` | 非空 | Argon2id 哈希，禁止保存明文密码 |
| `created_at` | `TIMESTAMPTZ` | 非空、默认当前时间 | 创建时间 |

## 约束

- 应用层保存前对 `user_name`、`email`、`nickname` 去除首尾空格。
- `email` 统一转小写；`user_name` 只允许小写。
- `nickname` 保存原始 Unicode 文字。
- 默认 `user_name` 使用 ICU4J `Any-Latin; Latin-ASCII` 生成，并清洗为 ASCII 用户名。
- 用户可以在最终提交前修改默认 `user_name`，但账户创建后不可修改。
- `nickname` 预览接口不预留用户名，最终注册仍以数据库唯一约束为准。
- 密码使用 NFC 规范化和 Argon2id 哈希，注册时执行本地弱密码 blocklist 检查。
- 重复 `user_name` 或 `email` 返回 HTTP `409 Conflict`。
- 其他表引用 `app_users.user_id`，不引用 `user_name`、`nickname` 或 `email`。
