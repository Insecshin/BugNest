# BugNest 模块与接口文档

本文记录当前代码实际提供的模块职责和 HTTP 接口。修改模块行为或接口时，先对照本文及对应设计文档；若实现发生变化，同步更新本文。

## 模块划分

| 模块 | 职责 | 主要类型 / 对外接口 |
| --- | --- | --- |
| `controller` | HTTP 路由与请求响应适配 | `AccountController`、`PingController`、`CsrfController` |
| `service` | 账户注册、用户名预览、昵称更新、密码与用户名规则 | `AccountService`、`PasswordPolicy`、`UsernameGenerator` |
| `repository` | 账户持久化访问 | `AccountRepository`、生产实现 `JdbcAccountRepository`（PostgreSQL/JDBC） |
| `model` | 账户领域数据 | `Account`；旧 `User` 仅用于内存兼容代码 |
| `dto` | HTTP 请求和响应结构 | `SignUpRequest/Response`、`UsernamePreviewRequest/Response`、`LoginRequest/Response`、`UpdateNicknameRequest`、`CsrfResponse`、`AuthenticationErrorResponse` |
| `security` | JSON 登录认证、会话、客户端 IP 解析和登录限流 | `JsonLoginAuthenticationFilter`、`AccountAuthenticationProvider`、登录成功/失败处理器、`LoginRateLimiter`、`AccountPrincipal` |
| `config` | Spring Bean、密码编码、Spring Security 与 Cookie/CSRF 配置 | `SecurityConfiguration`、`WebSecurityConfiguration` |
| `exception` | Controller 业务异常到 HTTP 状态的映射 | `GlobalExceptionHandler`、`AccountConflictException` |
| `db/migration` | PostgreSQL 表结构版本迁移 | Flyway `V1`、`V2` SQL 迁移 |

调用关系：`controller → service → repository`。登录由 Spring Security 过滤器链处理，不经过 MVC Controller。

## 通用约定

- 服务默认端口为 `8080`。
- 请求体和对象响应使用 JSON。
- 所有 POST、PATCH 等状态变更请求都受 CSRF 保护，包括登录、注册和用户名预览。先调用 `GET /auth/csrf` 获取 token，再将响应中的 token 放入其指定的请求头，并携带会话 Cookie。
- 登录成功使用服务器端 Session；Cookie 名为 `__Host-bugnest_session`，属性为 `Path=/; HttpOnly; Secure; SameSite=Lax`。Session 空闲超时为 30 分钟。
- 全局业务异常：参数错误 `400`、资源不存在 `404`、账户冲突 `409`。这类响应体为异常消息字符串。安全过滤器错误响应为 `{ "code": "...", "message": "..." }`。

## HTTP 接口

### 健康检查与示例

#### `GET /api/ping`

- 认证：匿名可访问。
- 成功：`200 OK`

```json
{
  "data": "pong",
  "message": "ok"
}
```

#### `GET /api/add?a=2&b=3`

- 认证：匿名可访问。
- 参数：必填整数 `a`；可选整数 `b`，默认值为 `1`。
- 成功：`200 OK`，响应体为整数，例如 `5`。

### 账户注册与资料

#### `POST /auth/sign-up`

- 认证：匿名可访问；需要 CSRF token。
- 请求：

```json
{
  "email": "user@example.com",
  "password": "至少 15 个字符",
  "confirmPassword": "至少 15 个字符",
  "nickname": "张三",
  "userName": "可选"
}
```

- 成功：`201 Created`

```json
{
  "userId": 123
}
```

- 失败：参数或密码策略不满足时 `400`；邮箱或用户名冲突时 `409`。
- `userName` 为空时按昵称生成；密码经 NFC 规范化后以 Argon2id 哈希保存。`confirmPassword` 不保存。

#### `POST /auth/sign-up/username-preview`

- 认证：匿名可访问；需要 CSRF token。
- 请求：

```json
{
  "nickname": "张三",
  "userName": "可选的手动用户名"
}
```

- 成功：`200 OK`

```json
{
  "userName": "zhang_san",
  "available": true
}
```

- `userName` 留空时根据昵称生成；填写时检查格式和可用性。预览不锁定用户名，注册仍可能因并发占用返回 `409`。

#### `PATCH /accounts/{id}/nickname`

- 认证：必须登录；仅能修改当前会话对应账户的昵称；需要 CSRF token。
- 请求：`{"nickname":"新昵称"}`
- 成功：`204 No Content`
- 失败：未登录 `401`、无权修改他人账户 `403`、昵称无效 `400`、账户不存在 `404`。

### 登录与 CSRF

#### `GET /auth/csrf`

- 认证：匿名可访问。
- 成功：`200 OK`；建立或沿用 CSRF 会话，并返回提交变更请求所需的请求头名称与 token。

```json
{
  "headerName": "X-CSRF-TOKEN",
  "token": "..."
}
```

- 以实际 `headerName` 为准，同时携带服务端返回的 Session Cookie。

#### `POST /auth/login`

- 认证：匿名可访问；需要 CSRF token。
- Content-Type：`application/json`。
- 请求：`{"identifier":"邮箱或用户名","password":"密码"}`
- 成功：`200 OK`，返回账户公开字段，并设置已轮换的 Session Cookie。

```json
{
  "userId": 123,
  "userName": "zhang_san",
  "nickname": "张三"
}
```

- 失败：请求格式错误 `400 INVALID_REQUEST`；凭证错误或账户不存在 `401 AUTHENTICATION_FAILED`；触发限流 `429 RATE_LIMITED` 并带 `Retry-After`；限流依赖不可用 `503 AUTHENTICATION_UNAVAILABLE`。
- 邮箱与用户名均可登录；账户不存在与密码错误返回相同响应。IP 令牌桶容量为 30、每分钟补充 30；账户连续失败后按递增等待时间限流，最长 15 分钟。

## 当前未启用的旧接口代码

`UserController` 中保留了旧 `/users` CRUD 代码，但它没有注册为 Spring MVC Controller，`UserService` 和 `MemoryUserRepository` 也未注册为生产 Bean。因此这些路由当前不属于可调用的 HTTP API。正式账户数据由 `AccountRepository` / `JdbcAccountRepository` 管理。
