# BugNest 前端界面与集成

## 目标与实现范围

把现有账户 API 变成可直接操作的中文界面，同时为缺陷管理提供可交互的工作台原型。界面采用深色终端风格：炭灰背景、金黄色强调色、顶部页面导航与侧栏、紧凑表格和小圆角。状态与优先级同时使用文字和图形表达，绿色表示解决或成功，红色表示紧急或错误。

页面文案仅保留功能标题、数据说明、输入指导、错误与状态反馈；不展示广告语、英文装饰标题、宣传页脚或虚构提示。登录注册页使用居中表单，保留品牌标识与返回工作台入口。

| 路由 | 功能 |
| --- | --- |
| `/` | 状态数量、解决率、未解决缺陷优先级分布、缺陷列表与看板 |
| `/issues` | 搜索标题/编号/负责人，按状态、优先级、项目筛选，新建与编辑示例缺陷 |
| `/login` | 邮箱或用户名登录，错误反馈、登录限流倒计时 |
| `/register` | 昵称、可选用户名、邮箱、密码确认、用户名预览与注册结果 |
| `/settings` | 从当前会话读取真实账户，修改本人昵称 |

缺陷后端尚未实现，因此示例缺陷保存在当前页面运行时的内存中，刷新后重置。概览所有数字从同一组示例缺陷计算，搜索、筛选、新建、状态修改与看板相互一致。页面明确标注演示状态，不能用来保存实际团队缺陷。登录不会将演示数据变成服务器业务数据。

## 技术与目录

`frontend/` 为独立 Vite 工程，按页面拆分 Vue 单文件组件。Vue Router 使用 HTML5 history，懒加载各页面。Element Plus 提供输入框、下拉筛选、按钮、表单及抽屉，品牌样式使用原生 CSS 定制。

稳定版本按 2026-10-09 官方 npm registry 的 `latest` 与实际编译兼容性确认，锁定在 `package.json` 与 `package-lock.json`：Vue 3.5.43、Vue Router 5.4.0、Vite 8.3.4、Element Plus 2.14.7。TypeScript 最新 7.0.2 与当前 `vue-tsc` 3.3.12 存在 `ERR_PACKAGE_PATH_NOT_EXPORTED` 编译问题，因此使用最新兼容稳定版本 6.0.3；不使用预发布版本。

- `src/api.ts`：标准 Fetch、同源 Cookie、CSRF、JSON/文本错误转换、`Retry-After`。
- `src/session.ts`：内存中的公开账户字段与刷新恢复；没有引入 Pinia。
- `src/issues.ts`：当前演示缺陷和固定状态/优先级定义。
- `src/validation.ts`：与后端一致的 Unicode 密码及昵称长度校验。
- `src/views/`：工作台、账户页面与未找到页面。
- `src/style.css`：品牌色、响应式布局、可见键盘焦点、减少动画偏好。

字体使用 Google Fonts 的 Pixelify Sans（英文、数字）与 DotGothic16（其覆盖的中文字形），保留 Noto Sans SC 和本机中文字体作为缺失字形或网络不可达时的回退。通过 HTML 字体样式链接和 preconnect 加载，不再从 CSS 导入旧字体。数字、编号、标题与导航使用像素字体；正文保留足够字号和行高。没有引入图片素材或图表库，圆环及优先级条用 CSS 绘制。

Element Plus 启用内置 dark 主题，并通过 CSS 变量统一输入框、下拉菜单、抽屉、消息提示和按钮的背景与颜色。像素图标与站点 `theme-color` 同步使用深色与金黄色，手机端继续使用侧栏抽屉和纵向缺陷条目。

## 账户与安全约定

1. 所有状态变更请求先获取 `/auth/csrf`，使用响应指定的 `headerName` 和 `token`，Fetch 设置 `credentials: same-origin`。
2. 登录、注册、用户名预览和退出均保留后端 CSRF 验证；登录/退出后不复用旧 token。
3. 登录成功仅把公开账户字段放入 Vue 内存。刷新通过 `GET /accounts/me` 恢复；不将密码、Cookie、token 或账户凭据写入 `localStorage`/`sessionStorage`。
4. 昵称修改只提交当前账户 ID；后端继续校验本人权限。当前账户接口从 Repository 读取最新昵称，不读取 Session 内可能过期的昵称副本。
5. 退出使用 Spring Security 的 `POST /auth/logout`，验证 CSRF 后清除认证并使 Session 失效，返回 `204`。
6. 密码校验使用 NFC 后的 Unicode code point 数量，支持 15–1024 个字符，保留空格，不增加特殊字符组合要求。弱密码阻止列表仍由后端负责。
7. 用户名预览等待输入停止约 500ms；输入改变或离开页面时取消旧请求，避免旧结果覆盖新输入。预览不预留用户名，最终注册仍以数据库约束为准。
8. 注册成功在当前注册页面展示结果，不直接刷新浏览器或因请求跳转 URL；用户点击登录后再导航。
9. 一次完整 API 操作最多等待 8 秒，覆盖 CSRF 获取、实际请求及响应体读取；写请求不自动重试。超时显示中文提示并由页面原有 finally 恢复按钮；用户名预览的主动取消继续保留。
10. 会话恢复使用请求版本检查；登录、成功退出、昵称更新及 401 清理通过统一的 `setAccount` 更新状态，使旧恢复响应失效。旧请求的成功、失败或 finally 都不得覆盖较新的账户和加载状态；退出失败不清空账户。

## 开发与发布

Vite 在 `https://localhost:5173` 开发，代理 `/auth`、`/accounts`、`/api` 到后端 `8080`。官方 `@vitejs/plugin-basic-ssl` 生成开发预览证书；生产应由 HTTPS 入口提供有效证书。

Maven 的 `prepare-package` 阶段执行 npm 安装、类型检查、Vite 构建及静态资源复制，最终 JAR 内包含 `static/index.html`、`static/assets` 和图标。`mvn test` 不需要先构建前端；`mvn package` 会构建前端，避免发布缺失界面的 JAR。

`FrontendController` 只将上述五个前端 GET 路由转发到 `index.html`。Security 配置仅匿名放行这些页面、入口及 `/assets/**` 等静态资源，未使用吞掉 API 的全路径 fallback。

## 验证

- Node 原生测试：CSRF token 与指定头、同源会话、CSRF 服务异常时禁止提交、JSON/纯文本/HTML 错误、限流等待时间、请求取消及 Unicode 校验。
- 后端 MVC 安全测试：前端路由匿名访问、API 继续受保护、当前会话 ID 与公开响应字段、无 CSRF 时禁止退出、退出使 Session 失效。
- 账户 Service 测试：更新昵称后读取最新公开信息、不存在账户返回错误。
- 浏览器检查：桌面/手机布局、列表搜索与空状态、新建缺陷、看板、刷新重置、注册校验、用户名预览、注册成功留在原页面、登录、昵称修改、会话恢复与退出。账户请求使用测试桩；真实 PostgreSQL/Redis 流程由已有 Testcontainers 测试覆盖。

完整数据库与 Redis 集成验证需要 Docker。运行方法见仓库 README。
