
# `POST /auth/login` 登录业务链

## 方案结论

是。由 Spring Security 的认证过滤器管理登录流程，比在 Controller 中手动设置并保存 `SecurityContext` 更合适，也更不容易漏掉会话轮换和认证生命周期处理。

JSON 登录需要自定义认证过滤器；显式配置 Spring Security 的 `SessionAuthenticationStrategy` 和基于 Session 的 `SecurityContextRepository`，之后由过滤器链完成认证上下文持久化，而不是由 Controller 手动保存。注意：现代 Spring Security 不应依赖未配置的默认行为；自定义过滤器必须接入这些组件。[Spring Security 认证过滤器](https://docs.spring.io/spring-security/reference/api/java/org/springframework/security/web/authentication/AbstractAuthenticationProcessingFilter.html) [认证架构](https://docs.spring.io/spring-security/reference/servlet/authentication/architecture.html)

## 实现与接口

- 使用 Spring Security `SecurityFilterChain`，由匹配 `POST /auth/login` 的 JSON 认证过滤器解析请求，并交给 `AuthenticationManager` / 自定义 `AuthenticationProvider`。Provider 复用 `AccountRepository` 和 Argon2id，按邮箱或用户名查账户。
- 请求为 `{"identifier":"邮箱或用户名","password":"密码"}`；成功返回 `200` 和 `{userId,userName,nickname}`，不返回邮箱、密码或哈希。
- 登录密码为 `null` 或空字符串时返回 `400 INVALID_REQUEST`，不进入账户认证；保留密码空格，不使用 `isBlank()` 拒绝只含空格的密码。
- 密码继续使用注册时的 NFC 规范化；未知账户也执行 dummy Argon2 校验。未知账户和密码错误均返回相同的 `401` 响应。
- 认证成功后，由 Spring Security 执行 Session ID 轮换并通过显式配置的 `SecurityContextRepository` 保存认证状态。Session 使用 Spring Session Redis，空闲超时 30 分钟；Cookie 为 `HttpOnly; Secure; SameSite=Lax; Path=/`，不设置 `Domain`。[Spring Session Redis](https://docs.spring.io/spring-boot/reference/web/spring-session.html)
- 配置 CSRF 防护及 `GET /auth/csrf` token 引导接口。登录、注册和其他 Cookie 认证下的状态变更请求都校验 CSRF；认证成功后刷新 token。
- 路由规则：登录、注册、用户名预览、CSRF 获取、`/api/ping`、`/api/add` 允许匿名访问；昵称修改要求登录，并校验路径账户 ID 与会话用户 ID 一致；其他路由默认要求认证。
- 增加 Spring Security 和 Spring Session Redis 的 Spring Boot 管理依赖；不改现有数据库迁移。

## Redis 限流

- IP 维度采用令牌桶：容量 30，每分钟补充 30 个令牌；登录请求均消耗令牌。只信任配置过的反向代理转发 IP。
- 账户维度按 `accountId` 统计，使邮箱和用户名共用失败次数；未知标识以密钥化 HMAC 生成 Redis 键，避免保存原始标识。
- Redis Lua 原子检查冷却并取得 10 秒认证租约；同一账户在租约有效期间仅允许一个密码校验，其余请求返回 `429`、`Retry-After: 1`，不增加失败次数。不同账户可并发。租约键为账户/未知标识限流键加 `:inflight`，值为独立随机持有者令牌。
- 成功、失败记录及释放均核对持有者令牌；成功和失败记录与租约释放原子完成。过期请求不得更新失败状态、删除新租约或建立会话，返回 `503`；异常退出释放自己的租约，进程退出则最多等待租约自然过期。沿用当前单 Redis 部署。
- 前 5 次连续失败不延迟；第 5 次失败后，后续尝试等待 30 秒，之后每次失败将等待时间翻倍，最多 15 分钟。冷却期间的请求不延长等待；成功登录清除账户失败状态；24 小时无失败后状态过期。
- 用 Redis Lua 原子更新限流状态。超限返回 `429` 和 `Retry-After`；Redis 不可用时失败关闭，返回 `503` 并记录告警。NIST要求限制账户失败认证次数；OWASP同时提醒账户锁定会带来拒绝服务风险，因此采用有上限的渐进延迟，不做永久锁号。[NIST](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/) [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)

## 测试与验收

- 覆盖邮箱/用户名登录、规范化、Argon2 校验、未知账户 dummy 校验及统一失败响应。
- 覆盖登录后 Session ID 轮换、后续请求恢复认证、CSRF 校验，以及本人/他人昵称修改权限。
- 覆盖 IP 令牌桶、账户渐进退避、冷却期不延长、别名共用计数、成功清零、状态过期、`429`/`Retry-After` 和 Redis 故障 `503`。
- 使用 Testcontainers 覆盖 PostgreSQL 与 Redis 集成；验证日志不包含密码、哈希、Session ID、Cookie 或原始登录标识。

## 依赖故障与超时

- `/auth/*`、`/accounts/*`、`/api/*` 使用位于 Spring Session 之前的依赖故障过滤器。API 响应先缓冲，待会话保存完成后发送，避免保存失败仍返回登录成功。只将连接、网络读写和资源超时错误映射为 `503 AUTHENTICATION_UNAVAILABLE`；其他程序错误继续交给服务器错误处理。
- 数据库连接池获取连接最多等待 2 秒，校验连接 1 秒；PG 驱动连接/读取超时各 2 秒、取消请求超时 1 秒，JdbcTemplate 查询超时 2 秒。Redis 连接和命令超时各 2 秒。停止依赖的复测要求 5 秒内返回 503；这些单项配置不是所有请求的硬性总时限，运维覆盖 JDBC URL 参数时也须保持预算一致。
- 邮箱查询使用 `lower(btrim(email)) = ?`，匹配已有的大小写不敏感唯一索引，不改变已执行迁移。

## 前端集成补充

- `GET /accounts/me` 要求认证，根据会话账户 ID 从 Repository 读取最新 `{userId,userName,nickname}`，用于页面刷新后恢复账户信息；不返回邮箱或哈希。
- `POST /auth/logout` 由 Spring Security 验证 CSRF 并注销 Session，成功返回 `204`。浏览器内存状态仅在退出成功后清除。
- 只匿名放行显式前端 GET 页面、入口和静态资源，其他接口仍保持认证规则；详情见 [`前端界面设计.md`](前端界面设计.md)。
- 开发预览使用 HTTPS，保留 `__Host-bugnest_session` 的 Secure 属性；线上需有效 HTTPS 入口。
